# Plan: mission library, safe custom missions, empty maps

Status: implemented 2026-09-17. In-game checks left, marked **(in game)** below.

## Why

On 2026-09-17 mission 15 lost all its guards: "Build new on mission 15" was
applied. That mode strips every shipped guard, and the base it strips is the
slot itself. Every Apply built on the previous Apply, so:

- a single Apply could destroy earlier work, with no way back,
- a plan's changes vanished into the slot once applied,
- a mission was two things at once, a browser save and a game slot.

What we know about the game:

- Missions are data-driven. The engine scans `missions/location0/*/mission.qvm`
  for `DefineMission(n, name, desc, "", next, dir, common, dir, "location0",
  "<resource base>", "<sprite>")`. Slot 15 is `level15`, a copy of `level1`
  with `DefineMission(15, "EXPERIMENT 15", …, "level1", "mission1.spr")`.
- The in-game mission list is a `ScrollListBox` filled by
  `Config_FillMissionSelectionBox()`, so slots 16+ should list too. Not yet
  tested in game.
- In-game covers are in `menusystem/missionsprites.res`: `mission1`…`mission14`,
  168×124 LOOP textures, ARGB1555, pixel data at offset 84.
- Names and descriptions are `language/USA/missions.res` CSTR entries
  (Trainyard, SAM Base, Military Airbase, GOD, Radar Base, Get Priboi, Border
  Crossing, Re-supply, Missile Trainyard, Defend Priboi, Eagle's Nest I/II,
  Nuclear Infiltration, Finding the bomb).
- A map's look comes from its terrain folder plus `GlobalLight`, `Dirlight`
  (+keyframes), `FlatSky` (+layers), `RainEffect` (rain or snow),
  `TerrainLightMap`, `HeightMap`. `DiscardTerrain` cuts holes under bunkers,
  so an empty map must drop it with the buildings.
- Mission 15 before the loss (git `488206d`, `editor/data/level15.json`) was
  level 1 plus 8 guards, 20 EditRigidObj and 3 GunPickups. Nothing shipped was
  removed or moved. Node 39 was moved by hand. The barracks interior, cut
  links and tower platform are regenerated by Apply.

## Model

| | Built-in mission | Custom mission |
|---|---|---|
| What | levels 1–14 as shipped | a project: a base + a plan |
| Stored | the game (never written) | `missions/custom/<id>/mission.json` (+ `cover.png`, `history/`) |
| In game | missions 1–14 | its own slot `level<M>`, M ≥ 15 |
| Actions | view, new mission from it | open, rename, duplicate, export, apply, remove from game, delete |

A custom mission's `base`:

- `{level: N, kind: "copy"}` — built-in mission N as shipped.
- `{level: N, kind: "empty"}` — N's terrain, sky, light and weather; no buildings,
  props, guards, pickups, vehicles or cutscenes.
- Copying a custom mission copies its base and plan.

**Apply always builds from the pristine base plus the whole plan.** It never
builds from the slot's previous state. Apply is repeatable, nothing accumulates,
and undo is just editing the plan.

The slot keeps a copy of `mission.json` (`_mission_studio.json`), so the game
folder alone is enough to recover a mission.

## Protection (built-in missions at all costs)

`studio/protect.py` is one gate that every writer calls:

- Refuses anything under the untouched reference copy of the game.
- In the working game, only `missions/location0/level<M>` with M ≥ 15 is
  writable. Refused: levels 1–14, `common`, `menusystem`, `language`, and
  everything else.
- Deleting a slot needs the studio marker, so a slot we didn't create is never
  deleted.
- Called by: `compile_qsc.install_level` / `install_graphs`, `model_import`
  import/repair/restore, slot create/rename/delete, server config (slot ≥ 15).
